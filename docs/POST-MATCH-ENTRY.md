## Captain workflow

Game Day → Record Event → **Record after game** opens the approved mobile form. Choose an existing past-kickoff match. First and second halves expand independently. Add a roster or match guest/TEMP player; set goal, yellow and red counts with large −/+ controls. Each goal has an assist selector: a stable player identity, No assist, or Unknown / not recorded. Assist counts follow goal links, so no orphan assists are created. TEMP jersey numbers may remain TBD because identity uses exact keys, not names or numbers.

Opponent goals are entered per half. Existing own goals, fouls, opponent cards and manual identity entries stay in the official log and totals; the form clearly lists these preserved entries and directs individual corrections to the existing event editor. Historical names/jerseys are never guessed into profiles. Current regular players, scoped event guests, match TEMP players and exact historical event identities are available; a promoted profile's existing TEMP alias is retained.

Existing supported events load into the form; counters represent desired totals. Removing newly added goals first preserves original event IDs when counts return to their original values. Adding an assist changes that goal's event; the same player cannot assist their own goal. A manually recorded historical assist stays unchanged until explicitly replaced. A summary shows score, goals, assists/cards, unknown assists, and numbers added/corrected/removed. Two yellows show a reminder to review whether a red also applies; red cards are not invented automatically.

**Save all events** submits both halves in one transaction. Mark match Final defaults on, making a completed match eligible for existing player record/stat calculations. It does not mark attendance. If a clock session exists, Final stops it at its real server-derived elapsed value; it does not fill in 90 minutes or create a clock/session. New post-match events have a selected half, `entry_source=post_match` and null official clock fields. New live events keep the existing clock stamping behavior. Existing live event timestamps, sequence, creation actor/date, source and unchanged identity/jersey fields survive corrections.

## Persistence and concurrency

- `get_post_match_editor(uuid)` is a guarded captain RPC returning one match, short display names/stable participant keys, official events and a digest revision. It exposes no emails or payment/feedback records.
- `save_post_match_events(uuid,uuid,text,jsonb,jsonb,boolean)` accepts only supported goal/card upserts and explicit existing-event deletions. It validates the half, target match, stable scorer/assist scope, identity uniqueness, self assists, array sizes and past kickoff. Names and numbers are resolved server-side; client-supplied presentation cannot impersonate a player.
- Upserts contain only actual semantic changes. Protected unsupported/manual events cannot be deleted through this API. Existing event IDs from another match are rejected. New rows are stamped as post-match; updates retain original live fields. Existing official event consumers remain the source for captain scores, personal records, guest/TEMP stats, season aggregates and AI match-event context. Public goal privacy and publication rules are unchanged.
- A private append-only `post_match_saves` receipt (cascaded only by explicit match deletion) stores request ID, real captain actor, match, submitted diff and result. Unchanged retries return the original result even after the revision changed; changed payloads or another actor cannot reuse an ID. Matching keys are checked before mutation and the whole transaction rolls back on any invalid row.
- Session→match locks follow clock-control ordering. A private owner-privilege match lock trigger also covers ordinary single-event inserts/updates/deletes, including unpublished matches while retaining the caller’s mutation RLS, so another captain's changes cannot slip past the event revision check. A racing row update may cause a database deadlock rather than lose changes; the editor treats serialization/deadlock errors as a conflict and requires reload/review.
- Digests cover events, match status/update and clock state/update. Stale saves cannot silently overwrite another captain. Drafts remain visible on a network failure and reuse the same request ID for an unchanged retry. Confirmed saves disable resubmission. Account/match/role changes clear drafts and ignore late responses. No local browser storage of these drafts is added.
- The private audit has RLS and no client grants. Internal helpers are revoked; only two guarded public RPCs are granted to authenticated users. View-only captains, regular players, guests and anonymous users cannot use the bulk editor APIs.
