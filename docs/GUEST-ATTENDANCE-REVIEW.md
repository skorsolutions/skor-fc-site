The guest directory previously showed only the confirmed Present count in the Games attended tile, with unmarked records further down. A captain could interpret one confirmed attendance as only one saved game. The new Captain-only presentation explicitly shows **1 confirmed · 2 games need confirmation** and **3 completed games on this record** when those are the stored counts. It does not substitute planned matches for confirmed attendance.

A Guest/TEMP card's summary has a pending-confirmation badge. Opening the profile shows a dated question: **Did this player attend these games?** Up to three dates are listed directly, with a clear Yes button for exactly those dates and an individual review option. Larger lists require individual review so captains see the dates before confirming. A review shows at most 50 dates per save and clearly leaves any remaining dates for another review.

Individual selectors start **Unmarked — decide later**. A captain may explicitly choose Present, Absent or Excused, leaving other dates unchanged. Opening, polling, refreshing, creating a guest or connecting old identities never marks anyone Present. Closing without choices keeps all dates Unmarked. No actual historical attendance was inferred or confirmed by preparing/deploying this feature.

The question applies only to unmarked completed records already admitted by the existing participation rules. Created-only or draft-only TEMP entries do not become game records or attendance prompts. Confirmed dates are not asked again. Regular/promoted-player attendance remains in its existing Game Day workflow; this new batch review is for current Guest/TEMP profiles.

Saves use existing `manage_guest_profile('attendance')` requests under the authenticated captain session. They refresh first, validate the exact displayed player/date choices and reject observed changed statuses before writing or moving to the next date. Already verified target statuses are skipped; no extra games are added because a refreshed record contains new dates. Existing RPC writes are per-game transactions and retain their existing last-write behavior, not a new database compare-and-swap operation. Acknowledged requests are retired so a later new confirmation cannot reuse an obsolete receipt; unacknowledged failures retain exact IDs for retries. Interrupted reviews preserve completed changes and leave remaining dates for explicit review.

Changing account or captain permission, or closing/replacing a modal review, stops subsequent writes and suppresses stale/private completion UI. A review refresh reloads the current dates; it never submits decisions. Snapshot/schema problems disable confirmation until the record is complete and refreshed.

Roster, Guest/TEMP records, Game Day attendance, player match totals and optional fee proposals read the existing persisted attendance. This UI does not alter RSVP, jersey numbers/inventory, lineups, official scores/stats, guest identity links or ledger entries. It never creates guest fees automatically. The guest-only Player Portal keeps its default record markup; the clarified tile/question is Captain-only.
