# Match keepers — v58.7

**v58.9 organization update:** The player picker shows short names, primary numbers and one TEMP indication; dual numbers and keeper notes remain on the field and referee sheet. Match Fill-ins and Keepers now occupy separate panels below the field, side by side where space permits and stacked at full width on phones. Keep the full name in the clearly labeled referee-name form so PDF/Excel retain it; all ordinary player labels use short names. Potential Positions starts closed and can be opened by its summary. Closing it does not affect saved positions or the separate export option. No database or Edge Function work is required.

**v58.8 display update:** On the field, primary / spare order stays the same. Cover wears a large primary number with a small spare beside it; the starter in goal has a large keeper number and small primary beside it. This follows the user's approved draft. TEMP names such as `Anton- TEMP` and `Malik - TEMP` display the name and one separate TEMP badge, with wrapping and growing name plates rather than ellipses. HTML markers, lineup PNG/JPG, public Matches, Crowd and Strategy exports share the presentation. This changes no saved name, lineup data, referee sheet or AI context, and requires no migration or Edge Function deployment.

In Lineups, add the match squad to the field and Substitutes, then use **Keepers for this match**. The standard formation's GK starts as a regular keeper. Change his role to **starting temp keeper** when an outfield player is covering. Use **Assign another keeper** to add potential cover, and choose or type a keeper jersey number for each player. The spare-number suggestions start at 30 and can contain several numbers, such as `30, 31`.

Selecting a starter moves him into GK and puts a displaced standard-formation keeper on the bench. On a Freeform board, selecting a starter places a bench player near the goal and retains an existing field player's coordinates. Moving another player into the standard GK slot updates who is labeled as the starter. Cover can share the same spare number or use different ones.

With a regular keeper: `1 — Jordan (starting keeper)` and `12 / 30 — Alex (backup keeper)`. With temporary keepers: `12 / 30 — Alex (starting temp keeper)` and `15 / 30 — Joe (secondary temp keeper)`. A keeper wearing his own primary number shows it once. TEMP fill-in status remains separate from temporary keeper duty.

Save the variation to share assignments across captains/devices. Publish it as Production / Final, or use **Publish Current Board to Final**, to update Captain/Crowd Game Day and public Matches. PNG/JPG and the referee card use the current board. Referee PDF and Excel keep one row per player with both numbers and a parenthesized role; Excel uses a wrapped name/duty cell while retaining one-page print settings. Strategy imports keep a snapshot of the keeper duties. The pregame AI receives keeper roles and jersey numbers only through the existing protected lineup/strategy context.

Spare-number choices are stored in the variation and reused on new boards from the latest saved choice list. This single-team app has no separate multi-team preference store. Cross-match copying retains spare choices but clears keeper assignments; choose the destination keepers again. Removing a player from the active squad removes his keeper assignment. Roster numbers, event identities and physical jersey custody are never changed by this feature.

No database migration, schema, RLS or grant change is required. The existing lineup JSON stores `keeperPlan`. Browser rules in `keeper-plan.js` must match the packaged copy under `supabase/functions/generate-pregame-talk/keeper-plan.js`. The updated Edge Function retains JWT verification and captain checks. Deployment publishes the frontend through the existing main-branch Cloudflare integration and separately deploys the authenticated Edge Function.
